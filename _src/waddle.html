Windows apps, as Linux windows.

Waddle-LSW is a Linux subsystem for Windows applications. Each Windows app shows up on a Wayland desktop as its own native window, not trapped inside a virtual machine viewer.

How a window gets across

  1. TrackA lightweight Windows guest runs in a VM. Waddle follows each application window inside it individually.
  2. CaptureEach window's surface is captured with hardware acceleration, one window at a time instead of the whole screen.
  3. TransferFrames cross the VM boundary through IVSHMEM, a block of memory both sides can read and write.
  4. ComposeOn the host, every window becomes a native Wayland surface beside your Linux applications.

One command

The waddle command starts the background services on first use and gives you the guest, a Windows shell or a single program.

waddle
Starts the subsystem if it isn't running and opens an interactive Windows ConPTY session.
waddle exec -- cmd.exe /c "dir C:\\"
Runs one program inside the Windows guest.
waddle status
Shows the subsystem daemon and VM state. start and stop control it.
waddle fs test
Checks shared directory mappings and read and write access.

Built to be rebuilt

Per-window, not per-screen

Tracking individual windows is what lets Windows apps sit next to Linux ones instead of inside a full-screen viewer.

Shared memory, not a network

IVSHMEM gives both sides of the VM boundary the same memory, so frames don't take a trip through a virtual network stack.

Hermetic builds

Every external dependency is a Git submodule, so builds are reproducible and work offline.

git clone --recurse-submodules https://github.com/Kayyo321/Waddle-LSW.git
