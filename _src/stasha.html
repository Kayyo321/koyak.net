From source to binary

The compiler is six stages, each in its own part of the source tree. The safety guarantees all live in one of them.

  1. 1Preprocessor

    Handles imports and conditional compilation before anything is parsed, so platform-specific code never reaches the later stages.

  2. 2Lexer

    Turns source text into tokens, including storage qualifiers like stack, heap and tls, and permission markers like *r, *w and *rw.

  3. 3Parser

    Builds the syntax tree: structs with methods and destructors, tagged enums, pattern matching, defer, inline test blocks and the dotted module system.

  4. 4Analysis

    Where the safety lives. It checks pointer lifetimes, refuses permission widening, catches stack values escaping their scope and flags null dereferences, all at compile time.

  5. 5Codegen

    Lowers the checked tree to LLVM IR with debug info, so stasha inherits LLVM's optimiser and its list of targets.

  6. 6Linker

    Produces native executables plus static and dynamic libraries. C headers import directly, so stasha can be adopted one file at a time inside an existing C project.

Memory you can read

An excerpt from the allocator in stasha's examples. The type of every pointer tells you where it lives and what you can do with it.

  1. 1heap is the storage class. Heap memory is explicit and freed automatically at scope exit.
  2. 2*rw is the permission: this pointer may be read and written. Widening a read-only pointer is a compile error.
  3. 3Functions return values and errors side by side, and errors are ordinary values.
// examples/allocator.sts
ext fn alloc_bytes(u64 size): [heap u8 *rw, error] {
    heap u8 *rw ptr = new.(size);
    if ptr == nil {
        ret nil, error.("tracked allocator: allocation failed for {} bytes", size);
    }

    this.allocations += 1;
    this.live_bytes += size;
    if this.live_bytes > this.peak_bytes {
        this.peak_bytes = this.live_bytes;
    }

    ret ptr, nil;
}

Checked before it runs

Pointer lifetime

A pointer can't outlive the storage it points into.

Permission widening

A read-only pointer can't quietly become writable.

Stack escape

Stack memory can't be returned or stored past its scope.

Null dereference

Possible nil values have to be handled before use.

No hidden allocation

No garbage collector and no implicit heap use, so performance stays predictable.

C interop

Import C headers and call C libraries directly over the C ABI.
