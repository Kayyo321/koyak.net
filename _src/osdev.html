What happens at power-on

      
Six steps from the BIOS to a running kernel. The map fills in as each part of memory gets used. It's in address order, not to scale.

    

    
    
      
  1. 1The BIOS finds the boot sector
    The BIOS loads the first 512 bytes of the disk to 0x7C00 and jumps there. Everything that follows has to start from those 512 bytes.
    2. 
      
  2. 2A stack, still in real mode
    The boot sector saves the boot drive number and points bp and sp at 0x9000, so it can call its own print routines.
    3. 
      
  3. 3Load the kernel from disk
    BIOS interrupt int 0x13 reads 15 sectors, starting at sector 2, into memory at 0x1000.
    4. 
      
  4. 4Switch to protected mode
    Interrupts off with cli, load the GDT with lgdt, set the PE bit in cr0, then a far jump to flush the CPU pipeline into 32-bit code.
    5. 
      
  5. 5A new stack, then the kernel
    Segment registers are reloaded and the stack moves up to 0x90000. The boot code calls the C kernel's entry point at 0x1000.
    6. 
      
  6. 6Draw to the screen
    The kernel turns on the x87 FPU by setting bits in cr0, renders the torus with fsin and fcos into an 80 × 22 buffer, and copies it to VGA text memory at 0xB8000.
    7. 
    

    

      
    

  






  

    

      
No libc, no SSE

      
The kernel is built with a cross compiler for a machine with nothing on it yet. Three flags carry most of that weight.

      


# Makefile
CC      = x86_64-elf-gcc
CFLAGS  = -ffreestanding -m32 -mno-sse
LD      = x86_64-elf-ld
LDFLAGS = -m elf_i386
ASM     = nasm
AFLAGS  = -f bin

      

    

    
    
      
  • -ffreestanding
    There's no hosted C library, so the kernel brings its own memory and formatting helpers.
    • 
      
  • -m32
    The code runs in 32-bit protected mode, matching the segments the boot sector sets up.
    • 
      
  • -mno-sse
    Nothing has enabled SSE registers yet. Floating point goes through the x87 FPU, which the kernel initialises itself.
    • 
      
  • -f bin
    The boot sector is assembled as a flat binary: exactly 512 bytes with no headers.
